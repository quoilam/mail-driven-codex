# mail-oo 实施计划

依据：[设计](design.md)与[真实邮件验证记录](mail-validation.md)。

已实现 Python 服务、SQLite 状态、收件解析、Codex 串行执行、SMTP 发件队列和 LaunchAgent 配置。真实往返与登录启动已联调；下列阶段保留为验收清单。

新部署使用被 Git 忽略的 `.env`；已有部署可继续使用 `.local/config.json`。配置包含邮件凭据、`gpt-6-luna` 和禁止模型回退的设置。配置不得上传或写入对外内容，在线仅将凭据用于认证。

## 阶段 1：固定集成接口

- 检查本机 Codex 版本与本地使用说明，确认非交互新建、指定目录、显式 session 恢复、最终答复和 session ID 的获取方法。
- 确认沿用现有登录及 YOLO 配置的调用方式，并验证如何终止整轮任务。
- 查明并验证 163 SMTP 的 TLS 和认证方式；不将已验证的 IMAP 能力当作 SMTP 能力。
- 固定 `/new` 路径语法、会话编号样式以及 `/resume` 的命令位置；推荐 `/resume` 同样放标题。
- 实现受限权限的本地配置读取，确认 163 收信认证头的可信校验方法。
- 验证本机 Codex 接受 `gpt-6-luna`；所有新建和恢复调用显式指定 Luna，不自动升级或回退到其他模型。
- 根据实际能力确定实现语言及依赖。建议优先用 Python + SQLite；Codex 集成方式由本机接口能力决定。

完成条件：新建、恢复、取结果、发结果的调用方式明确，Luna 模型约束已验证，未决配置已记录；授权码仅存于被忽略的本地配置文件，未进入版本控制。

## 阶段 2：可靠收件和任务入库

- 实现 TLS IMAP 连接、客户端 ID、断线重连和只读收取。
- 第一版建议定时轮询，例如每 30 秒一次；无需为无 ACK 的工作流引入额外即时机制。轮询间隔可配置。
- 首次启动建立基线；后续按 UIDVALIDITY/UID 游标补收，任务入库后推进游标。
- 在本地校验发件地址、认证结果和重复邮件，不依赖本次表现异常的服务端 FROM 搜索。
- 建立 SQLite 会话、邮件映射、任务队列及发件队列。

完成条件：只有允许来源的新邮件进入队列；重启不漏收、不重复执行；已读状态不受影响。

## 阶段 3：解析与路由

- 解析 MIME，优先纯文本，支持 HTML 回退。
- 根据已观察到的网易邮箱大师引用和签名结构提取新增正文。
- 提取完整 Message-ID；兼容无空格相邻的 References ID。
- 按回复关联、会话编号兜底、显式恢复、新建命令的规则路由；冲突或无法关联时报告错误。
- 校验路径，必要时创建目录，保存会话工作目录。
- 路由层只产出任务，不在邮件解析过程中执行 prompt。

完成条件：真实新建样本创建目标目录并提取本轮正文；回复样本只提取新增正文并指向原会话。

## 阶段 4：Codex 串行执行

- 实现全局单执行器与服务单实例保护。
- 新建任务保存明确的 session ID；继续任务恢复该 ID。
- 两种调用都显式传入 `gpt-6-luna`；不支持该模型时失败并说明原因，不使用其他模型替代。
- 保存最终答复、失败信息和本地诊断日志。
- 实现可配置的 60 分钟超时及受控子进程终止。
- 启动时恢复未开始任务，将中断执行标为需用户决定，不自动重跑。

完成条件：不同邮件线程具有独立 session；同一线程保留上下文；前一轮停止后才开始下一轮。

## 阶段 5：结果邮件与发件恢复

- 将最终答复或失败原因写入持久化发件队列。
- 固定回信地址为允许的 QQ 地址，不根据任意 Reply-To 改变目的地。
- 发出结果时设置 Message-ID、In-Reply-To、References 和标题会话编号。
- 发送前持久化 Message-ID 及映射；重试复用同一 Message-ID。
- 发信失败只重试寄信，不重跑 Codex；记录 SMTP 接收结果不确定的窗口。

完成条件：用户能对服务结果邮件正常回复并恢复 session；发信重试不会再次修改项目文件。

## 阶段 6：集成验证与部署

实现时进行下列针对行为的验证，避免仅验证代码内部结构：

| 场景 | 预期 |
| --- | --- |
| 标题 `/new` | 在 `~/Documents` 新建会话 |
| 标题 `/new testfolder`，目录不存在 | 创建目录并执行正文 |
| 绝对路径、越界路径、指向根目录外的符号链接 | 拒绝任务并向固定地址说明 |
| QQ 回复服务的结果邮件 | 恢复原 session，仅提交新增正文 |
| 回复标题保留 `/new` | 不误建会话 |
| 相邻 References ID 无空格 | 仍能关联 |
| 字段丢失但会话编号有效 | 使用编号恢复 |
| 关联冲突或未知编号 | 不执行，报告错误 |
| 非允许来源、认证失败、自动回复 | 不执行 |
| 重复收取、服务重启 | 不重复启动已执行任务 |
| 休眠或断网后恢复 | 补收积压任务并串行执行 |
| 执行中崩溃或超时 | 通知中断，不自动重跑 |
| 执行完成后 SMTP 失败 | 仅重试发送结果 |
| SMTP 成功后本地状态未落盘 | 记录可能重复结果邮件的限制 |

部署采用 macOS 登录启动机制，建议 LaunchAgent；配置绝对路径、环境、日志位置和停止方式。验证启动、停止、退出登录及唤醒后的行为。

补充运维文档：配置、允许发件人、凭据更新、日志查看、队列状态、备份、手动恢复和卸载。真实发信测试仅使用指定的用户 QQ 邮箱。

完成条件：当前客户端完整走通“新建 → 回信 → 回复继续”，关键恢复场景已验证，后台启动方式可重复操作。

## 第一版范围

第一版交付一个本地单用户服务，保留正文邮件交互、会话持久化和故障恢复。附件输入输出、多用户、并行执行、实时打断、网页控制台及其他客户端兼容性不属于当前范围。
